Every server must use one of the transport protocols approved by the organization, so that APIs only rely on brokers and transports the organization supports.

The rule checks the `protocol` of every server of the root `servers` object and of `components.servers`, in AsyncAPI 2.x and 3.x alike. The value is compared exactly, case included, with the configured list of allowed protocols; a protocol outside the list is reported, and so is a `protocol` that is not a string. A server without `protocol` is not reported by this rule. By default the list holds every protocol named by the AsyncAPI specification and its official bindings, so misspelled or unofficial values such as `Kafka`, `kafka-ssl` or `rabbitmq` are reported.

Parameters
----------

- `allowed-protocols` — comma-separated list of the allowed protocols, written as AsyncAPI `protocol` values, such as `kafka,kafka-secure`. Entries are trimmed, empty and repeated entries are ignored, and each protocol is compared exactly, case included. An empty value falls back to the default. Default: `amqp,amqp1,amqps,anypointmq,googlepubsub,http,https,ibmmq,ibmmq-secure,jms,kafka,kafka-secure,mercure,mqtt,mqtt5,nats,pulsar,redis,ros2,secure-mqtt,sns,solace,sqs,stomp,stomps,ws,wss`.

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
  staging:
    url: broker-pre.quality.es:9092
    protocol: kafka
channels: {}
```
