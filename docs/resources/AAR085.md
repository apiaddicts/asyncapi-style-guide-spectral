Every server must run an approved version of its protocol, so that clients and brokers are built against the versions the organization supports.

The rule checks the `protocolVersion` of every server of the root `servers` object and of `components.servers`, in AsyncAPI 2.x and 3.x alike. The value is compared, exactly as written, with the configured list of approved versions; a version outside the list is reported, and so is a `protocolVersion` that is not a string (for example an unquoted `3.0`, which YAML reads as a number). A server without `protocolVersion` is not reported by this rule.

Parameters
----------

- `valid-versions` — comma-separated list of the approved protocol versions, such as `3.6.0,3.7.0`. Entries are trimmed and compared exactly with each `protocolVersion`. An empty value falls back to the default. Default: `3.3.0`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    protocolVersion: 2.8.0 # Noncompliant {{AAR085: Server 'production' protocolVersion '2.8.0' must be an approved version: '3.3.0'.}}
  staging:
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
    protocolVersion: 3.0 # Noncompliant {{AAR085: Server 'staging' protocolVersion must be a string.}}
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    protocolVersion: 3.3.0
  staging:
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
    protocolVersion: '3.3.0'
channels: {}
```
