Tag names must follow the naming convention configured by the organization, kebab-case by default, so that tags group the elements of the document in a consistent way.

The rule checks the `name` of every Tag object in the document. In AsyncAPI 2.x these are the root `tags` and the tags of servers, `publish` and `subscribe` operations, messages (including each `oneOf` alternative), operation traits and message traits, both inline and in `components`. In AsyncAPI 3.x they are `info.tags` and the tags of servers, channels, operations, messages, operation traits and message traits, both inline and in `components`, plus the entries of `components.tags`.

A tag name that does not follow the convention, or that is not a string, is a violation.

Parameters
----------

- `naming-convention` — naming convention that tag names must follow. Accepted values: `kebab-case`, `camelCase`, `PascalCase` and `snake_case`; letter case, spaces, hyphens, underscores and a trailing `case` are ignored, so `kebab`, `camel`, `pascal` or `snake` also work, and `lowerCamelCase` and `UpperCamelCase` are accepted as camelCase and PascalCase. camelCase and PascalCase do not allow consecutive uppercase letters. An unrecognized value falls back to kebab-case. Default: `kebab-case`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
tags:
  - name: Order Management # Noncompliant {{AAR066: Tag name 'Order Management' must be kebab-case.}}
    description: Events of the order lifecycle.
channels:
  orders.placed:
    publish:
      operationId: publishOrderPlaced
      tags:
        - name: order_events # Noncompliant {{AAR066: Tag name 'order_events' must be kebab-case.}}
      message:
        messageId: orderPlaced
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
tags:
  - name: order-management
    description: Events of the order lifecycle.
channels:
  orders.placed:
    publish:
      operationId: publishOrderPlaced
      tags:
        - name: order-events
      message:
        messageId: orderPlaced
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  tags:
    - name: OrderManagement # Noncompliant {{AAR066: Tag name 'OrderManagement' must be kebab-case.}}
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        payload:
          type: object
operations:
  publishOrderPlaced:
    action: send
    channel:
      $ref: '#/channels/ordersPlaced'
    tags:
      - $ref: '#/components/tags/orderEvents'
components:
  tags:
    orderEvents:
      name: Order Events # Noncompliant {{AAR066: Tag name 'Order Events' must be kebab-case.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events

  tags:
    - name: order-management
channels:

          type: object

      $ref: '#/channels/ordersPlaced'

      - $ref: '#/components/tags/orderEvents'
```
