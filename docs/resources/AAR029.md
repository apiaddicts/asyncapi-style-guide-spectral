Every channel and every operation must have a `description` that explains its purpose.

In AsyncAPI 2 the rule checks every channel in `channels` and its `publish` and `subscribe` operations. In AsyncAPI 3 it checks every channel in `channels` and every operation in the root `operations` object. An element whose `description` is missing or empty is reported.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created: # Noncompliant {{AAR029: This element must have a 'description' field that explains its purpose.}}
    publish:
      operationId: publishOrderCreated
      description: "" # Noncompliant {{AAR029: This element must have a 'description' field that explains its purpose.}}
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    description: Events emitted when a customer places an order.
    publish:
      operationId: publishOrderCreated
      description: Publishes the order once the payment has been authorized.
      message:
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated: # Noncompliant {{AAR029: This element must have a 'description' field that explains its purpose.}}
    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object
operations:
  publishOrderCreated: # Noncompliant {{AAR029: This element must have a 'description' field that explains its purpose.}}
    action: send
    channel:
      $ref: '#/channels/orderCreated'
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    description: Events emitted when a customer places an order.
    messages:
      orderCreated:
        payload:
          type: object
operations:
  publishOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
    description: Publishes the order once the payment has been authorized.
```
