Every property name of the message schemas must follow the organization's naming convention, so that consumers find the same style of field names in every event.

The rule checks the names under `properties`, at any depth, and the `name` of every field of an Avro record, in the message payloads of channels, operations and `components`, in the schemas of AsyncAPI 2.x channel parameters and in every entry of `components.schemas`. In AsyncAPI 3.x a multi-format schema is read through its `schema`. Only JSON Schema, AsyncAPI, OpenAPI and Avro schemas are checked; other formats, such as RAML or Protobuf, are skipped. A schema reached through a `$ref` is checked once, at its definition.

A name that does not follow the convention is reported, and so is an Avro field name that is not a string. By default names must be camelCase: a lowercase first letter followed by letters and digits, with no two capital letters in a row, so `orderId` passes while `order_id` and `orderID` are reported. Message and message trait `headers` are never checked, nor a `components.schemas` entry used only as headers, so header names such as the CloudEvents `ce_type` are not reported; bindings and examples are not checked either.

Parameters
----------

- `naming-convention` — convention every property and Avro field name must follow: `camelCase`, `snake_case`, `kebab-case` or `PascalCase`. The value is not case-sensitive, and spaces, hyphens, underscores and a trailing `case` are ignored, so `snake` or `SNAKE_CASE` also select snake_case; `lowerCamelCase` and `UpperCamelCase` are read as camelCase and PascalCase. An empty or unknown value falls back to the default. Default: `camelCase`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    subscribe:
      message:
        payload:
          type: object
          properties:
            orderId:
              type: string
            customer_id: # Noncompliant {{AAR074: Property name 'customer_id' must be camelCase.}}
              type: string
            lines:
              type: array
              items:
                type: object
                properties:
                  UnitPrice: # Noncompliant {{AAR074: Property name 'UnitPrice' must be camelCase.}}
                    type: number
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    subscribe:
      message:
        headers:
          type: object
          properties:
            ce_type:
              type: string
            ce_specversion:
              type: string
        payload:
          type: object
          properties:
            orderId:
              type: string
            customerId:
              type: string
            lines:
              type: array
              items:
                type: object
                properties:
                  unitPrice:
                    type: number
```

asyncapi: 3.0.0
info:
  title: Orders Events

    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object

components:
  schemas:
    Shipment:
      schemaFormat: application/vnd.apache.avro;version=1.9.0

        type: record
        name: Shipment
