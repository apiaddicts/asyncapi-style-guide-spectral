Every channel must say what it is for and how it is used, so that it can be understood without reading the rest of the document.

The rule checks every channel of the root `channels` object and of `components.channels`. In AsyncAPI 3.x a channel must declare `address`, a non-empty `description` and `messages`: `address` may be `null`, which marks the address as unknown or dynamic, but must not be an empty string, and `messages` only has to be present, whatever its content. In AsyncAPI 2.x, where the channel key is the address, a channel must declare a non-empty `description` and a `publish` or `subscribe` operation.

A missing field or operation is reported on the channel name, and an empty field (a blank string, an empty object or an empty list, and also `null` for `description`) on the field itself. A channel that is not an object is reported too.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created: # Noncompliant {{AAR087: Channel 'orders.created' must declare 'description'.}}
    publish:
      operationId: publishOrderCreated
      message:
        payload:
          type: object
  orders.cancelled: # Noncompliant {{AAR087: Channel 'orders.cancelled' must declare a 'publish' or 'subscribe' operation.}}
    description: '' # Noncompliant {{AAR087: The 'description' of channel 'orders.cancelled' must not be empty.}}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    description: Orders that have just been created.
    publish:
      operationId: publishOrderCreated
      message:
        payload:
          type: object
  orders.cancelled:
    description: Orders cancelled by the customer.
    subscribe:
      operationId: consumeOrderCancelled
      message:
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated: # Noncompliant {{AAR087: Channel 'orderCreated' must declare 'messages'.}}
    address: orders.created
    description: Orders that have just been created.
  orderCancelled: # Noncompliant {{AAR087: Channel 'orderCancelled' must declare 'description'.}}
    address: '' # Noncompliant {{AAR087: The 'address' of channel 'orderCancelled' must not be empty.}}
    messages:
      orderCancelled:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    description: Orders that have just been created.
    messages:
      orderCreated:
        $ref: '#/components/messages/orderCreated'
  customerNotifications:
    address: null
    description: Notifications for each customer, on an address resolved at runtime.
    messages:
      customerNotification:
        payload:
          type: object
components:
  messages:
    orderCreated:
      payload:
        type: object
```
