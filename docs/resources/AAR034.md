The `format` of a numeric property must be one of the standard numeric formats: `int32`, `int64`, `float` or `double`.

The rule checks the properties, at any depth, of the schemas in `components.schemas`, of the `payload` of the messages in `components.messages` and of the `payload` of the messages written in the channels (in AsyncAPI 2 the `message` of each `publish` and `subscribe` operation, in AsyncAPI 3 each entry of the channel `messages`). References are not followed.

A property whose `type` is `integer` or `number` is reported when it declares a `format` that is not one of those four values. A numeric property without `format` is not reported.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      message:
        contentType: application/json
        payload:
          type: object
          properties:
            quantity: # Noncompliant {{AAR034: Numeric property must specify a valid 'format' (int32, int64, float, double).}}
              type: integer
              format: int
components:
  schemas:
    OrderLine:
      type: object
      properties:
        price: # Noncompliant {{AAR034: Numeric property must specify a valid 'format' (int32, int64, float, double).}}
          type: number
          format: decimal
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      message:
        contentType: application/json
        payload:
          type: object
          properties:
            quantity:
              type: integer
              format: int32
components:
  schemas:
    OrderLine:
      type: object
      properties:
        price:
          type: number
          format: double
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        $ref: '#/components/messages/OrderCreated'
components:
  messages:
    OrderCreated:
      contentType: application/json
      payload:
        type: object
        properties:
          createdAt: # Noncompliant {{AAR034: Numeric property must specify a valid 'format' (int32, int64, float, double).}}
            type: integer
            format: unix-time
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        $ref: '#/components/messages/OrderCreated'
components:
  messages:
    OrderCreated:
      contentType: application/json
      payload:
        type: object
        properties:
          createdAt:
            type: integer
            format: int64
```
