Every security scheme must be of a type allowed by the organization and must define the fields that its type needs to work.

The rule checks every scheme in `components.securitySchemes`, in both AsyncAPI 2.x and 3.x. A scheme is reported when it has no `type`, when its `type` is not in the allowed list, or when it is incomplete for its type:

- `http` must define `scheme`.
- `apiKey` and `httpApiKey` must define `in`.
- `oauth2` must define a `flows` object.
- `openIdConnect` must define `openIdConnectUrl`.

Parameters
----------

- `allowedTypes` — security scheme types the organization accepts, as a list of `type` values. An empty list accepts any type and only checks completeness. Default: `userPassword`, `apiKey`, `X509`, `symmetricEncryption`, `asymmetricEncryption`, `httpApiKey`, `http`, `oauth2`, `openIdConnect`, `scramSha256`, `scramSha512`, `gssapi`, `plain`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - saslScram: []
channels: {}
components:
  securitySchemes:
    saslScram:
      type: scramSha512
    legacyToken:
      type: customToken # Noncompliant {{AAR018: The security scheme must be among those allowed by the organization and must be complete}}
    bearerToken: # Noncompliant {{AAR018: The security scheme must be among those allowed by the organization and must be complete}}
      type: http
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - saslScram: []
channels: {}
components:
  securitySchemes:
    saslScram:
      type: scramSha512
    bearerToken:
      type: http
      scheme: bearer
      bearerFormat: JWT
```

Noncompliant Code Example (AsyncAPI 3)

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    host: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - $ref: '#/components/securitySchemes/saslScram'

  securitySchemes:
    saslScram:
      type: scramSha512
    partnerKey: # Noncompliant {{AAR018: The security scheme must be among those allowed by the organization and must be complete}}
      type: httpApiKey
      name: X-Api-Key
    ordersOAuth: # Noncompliant {{AAR018: The security scheme must be among those allowed by the organization and must be complete}}
      type: oauth2
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    host: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - $ref: '#/components/securitySchemes/saslScram'
components:
  securitySchemes:
    saslScram:
      type: scramSha512
    partnerKey:
      type: httpApiKey
      name: X-Api-Key
      in: header
    ordersOAuth:
      type: oauth2
      flows:
        clientCredentials:
          tokenUrl: https://auth.quality.es/oauth2/token
          availableScopes:
            orders:read: Read order events.
```
