Every content type declared in the document must be a valid MIME type from the list allowed by the organization, so that producers and consumers agree on how messages are encoded.

The rule checks the root `defaultContentType` and the `contentType` of every message and message trait in `channels`, `components.channels`, `components.messages` and `components.messageTraits`. In AsyncAPI 2.x the messages are those of the `publish` and `subscribe` operations, including each `oneOf` alternative; in AsyncAPI 3.x they are the entries of the channel `messages` maps.

A value that is not a well-formed MIME type (`type/subtype`, optionally followed by parameters such as `; charset=utf-8`), or whose type and subtype are not in the allowed list, is a violation. Parameters are ignored when comparing with the list.

Parameters
----------

- `allowed-content-types` — comma-separated list of the allowed media types, written as `type/subtype`. Entries are case-insensitive, any parameters in them are ignored, and `*` matches any run of characters inside the type or the subtype, so `application/*+json` accepts `application/cloudevents+json`. Entries that are not valid media types are discarded; when no entry is valid, the default list applies. Default: `application/json,application/*+json,application/xml,application/*+xml,text/xml,text/plain,text/csv,application/octet-stream,application/avro,application/*+avro,application/protobuf,application/x-protobuf,application/cbor,application/yaml`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: json # Noncompliant {{AAR067: defaultContentType 'json' is not a valid MIME type.}}
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        contentType: text/html # Noncompliant {{AAR067: contentType 'text/html' is not an allowed MIME type.}}
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: application/json
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        contentType: application/cloudevents+json; charset=utf-8
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: application/json
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        contentType: application/x-www-form-urlencoded # Noncompliant {{AAR067: contentType 'application/x-www-form-urlencoded' is not an allowed MIME type.}}
        payload:
          type: object
components:
  messageTraits:
    avroEncoded:
      contentType: avro # Noncompliant {{AAR067: Message trait contentType 'avro' is not a valid MIME type.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: application/json
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        contentType: application/json
        payload:
          type: object
components:
  messageTraits:
    avroEncoded:
      contentType: application/avro
```
