Every message must declare its `contentType`, so that consumers know how to decode the payload. Avro messages are exempt, because their schema format already defines the encoding.

The rule checks the messages of the channels in `channels` and `components.channels` (in AsyncAPI 2 the `message` of each `publish` and `subscribe` operation, in AsyncAPI 3 each entry of the channel `messages`) and every message in `components.messages`, including each alternative of a `oneOf`. A message given as a `$ref` is checked once, where it is defined. A `contentType` inherited from a message trait counts as declared, and the root `defaultContentType` does not.

A message is reported when its `contentType` is missing or `null` and neither the message nor its `payload` has a `schemaFormat` that contains `application/vnd.apache.avro`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      message: # Noncompliant {{AAR024: Each message must declare a 'contentType' unless it is an Avro message}}
        name: OrderCreated
        payload:
          type: object
  orders.cancelled:
    subscribe:
      message:
        $ref: '#/components/messages/OrderCancelled'
components:
  messages:
    OrderCancelled: # Noncompliant {{AAR024: Each message must declare a 'contentType' unless it is an Avro message}}
      name: OrderCancelled
      contentType: null
      payload:
        type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      message:
        name: OrderCreated
        contentType: application/json
        payload:
          type: object
  orders.cancelled:
    subscribe:
      message:
        $ref: '#/components/messages/OrderCancelled'
components:
  messages:
    OrderCancelled:
      name: OrderCancelled
      schemaFormat: application/vnd.apache.avro;version=1.9.0
      payload:
        type: record
        name: OrderCancelled
        fields:
          - name: orderId
            type: string
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated: # Noncompliant {{AAR024: Each message must declare a 'contentType' unless it is an Avro message}}
        name: OrderCreated
        traits:
          - $ref: '#/components/messageTraits/CommonHeaders'
        payload:
          type: object
components:
  messageTraits:
    CommonHeaders:
      headers:
        type: object
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        name: OrderCreated
        traits:
          - $ref: '#/components/messageTraits/CommonHeaders'
        payload:
          type: object
  orderCancelled:
    address: orders.cancelled
    messages:
      orderCancelled:
        name: OrderCancelled
        payload:
          schemaFormat: application/vnd.apache.avro;version=1.9.0
          schema:
            type: record
            name: OrderCancelled
            fields:
              - name: orderId
                type: string
components:
  messageTraits:
    CommonHeaders:
      contentType: application/json
      headers:
        type: object
```
