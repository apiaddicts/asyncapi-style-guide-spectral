In the Kafka context, every server must use the `kafka` or `kafka-ssl` protocol. Other protocols, such as `https` or `wss`, are not permitted.

The rule checks the `protocol` of every server under the root `servers` and under `components.servers`, in both AsyncAPI 2.x and 3.x. The value must be exactly `kafka` or `kafka-ssl` (the comparison is case-sensitive and does not trim spaces). Any other value, including a number, a boolean, an object or an array, is a violation. A server without `protocol` is not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:443
    protocol: https # Noncompliant {{AAR064: The server protocol must be 'kafka' or 'kafka-ssl'. Found 'https'.}}
  staging:
    url: broker-pre.quality.es:9092
    protocol: Kafka # Noncompliant {{AAR064: The server protocol must be 'kafka' or 'kafka-ssl'. Found 'Kafka'.}}
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-ssl
  staging:
    url: broker-pre.quality.es:9092
    protocol: kafka
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/production'
components:
  servers:
    production:
      host: broker.quality.es
      pathname: /ws
      protocol: wss # Noncompliant {{AAR064: The server protocol must be 'kafka' or 'kafka-ssl'. Found 'wss'.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/production'
components:
  servers:
    production:
      host: broker.quality.es:9093
      protocol: kafka-ssl
```
