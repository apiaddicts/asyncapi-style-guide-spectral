Every message must apply message traits, so that the headers, bindings and metadata shared by all messages are declared once and reused consistently.

The rule checks every message defined in the document: in AsyncAPI 2.x, the `message` of the `publish` and `subscribe` operations of each channel of the root `channels` object and of `components.channels` (each `oneOf` member counts as a message), and every entry of `components.messages`; in AsyncAPI 3.x, the `messages` map of each channel of the root `channels` object and of `components.channels`, and every entry of `components.messages`. A message given as a `$ref` is checked where it is defined. Traits applied to an operation do not count for its message.

By default each message must declare `traits` as an array with at least one valid trait: a non-empty trait object, written inline or reached through a reference. A message without `traits` is reported on the message itself; a `traits` value that is not an array, or an array without any valid trait (empty, or holding only empty objects or references that do not resolve), is reported on the `traits` field. When the organization requires specific traits, each one the message does not apply is reported instead.

Parameters
----------

- `required-traits` — comma-separated list of trait names, keys of `components.messageTraits`, that every message must apply, such as `commonHeaders,tracing`. Entries are trimmed and compared exactly with the trait names. A trait counts as applied only when an entry of `traits` is a `$ref` to a valid trait at `#/components/messageTraits/<name>`, directly or through a chain of local references, or an external reference whose fragment is `/components/messageTraits/<name>`; inline traits never count, even when their content is the same. Each missing trait is reported once per message. Default: empty, which requires no specific trait: every message must then apply at least one valid trait.

        type: object

            type: string
