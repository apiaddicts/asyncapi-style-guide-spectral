The license of the API must be named with a standard identifier, so that people and tools know exactly which terms apply to it.

The rule checks `info.license.name`, in AsyncAPI 2.x and 3.x alike. The name must be, with exactly that spelling and case, an identifier of the SPDX License List 3.29.0, such as `Apache-2.0`, `MIT` or `BSD-3-Clause` (deprecated identifiers such as `GPL-2.0` are accepted too), or a `LicenseRef-<idstring>` identifier for a license outside that list, where the idstring is made of letters, digits, `.` and `-` (for example `LicenseRef-Quality-Internal`).

A descriptive name such as `Apache License 2.0`, a license expression such as `MIT OR Apache-2.0`, or a value that is not a string is a violation. When the name differs from a valid identifier only in case, in spaces instead of hyphens or in surrounding whitespace, the message names the identifier to use. A license without `name`, or with an empty one, is not reported by this rule, and licenses outside `info` are not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  license:
    name: Apache License 2.0 # Noncompliant {{AAR080: The license name 'Apache License 2.0' must be an SPDX license identifier, such as 'Apache-2.0' or 'MIT', or a 'LicenseRef-' identifier.}}
    url: https://www.apache.org/licenses/LICENSE-2.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  license:
    name: Apache-2.0
    url: https://www.apache.org/licenses/LICENSE-2.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
channels: {}
```
