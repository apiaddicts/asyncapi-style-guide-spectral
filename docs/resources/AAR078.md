The API must state the terms under which it can be used, so the `info` object must declare a `license` object with a non-empty `name` and `url`.

The rule checks `info.license` in AsyncAPI 2.x and 3.x alike. A document without `info`, an `info` without `license`, a `license` that is not an object, a missing `name` or `url`, or one of them empty (`null`, or a string made only of whitespace) is a violation.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  license: # Noncompliant {{AAR078: The 'license' object must declare 'url'.}}
    name: Apache-2.0
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  license:
    name: Apache-2.0
    url: https://www.apache.org/licenses/LICENSE-2.0
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info: # Noncompliant {{AAR078: The 'info' object must declare a 'license' object with 'name' and 'url'.}}
  title: Orders Events
  version: 1.0.0
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  license:
    name: Apache-2.0
    url: https://www.apache.org/licenses/LICENSE-2.0
```
