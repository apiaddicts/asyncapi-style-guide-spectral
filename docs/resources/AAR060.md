Message content types must match `application/*+avro` (e.g. `application/vnd.orders.v1+avro`), so that Confluent's `KafkaAvroDeserializer` can deserialize the payload.

The rule checks the root `defaultContentType` and the `contentType` of every message: the messages of channel operations (`publish`/`subscribe`) in AsyncAPI 2.x, the messages of channels in AsyncAPI 3.x, and the messages under `components.channels`, `components.messages` and each `oneOf` alternative. When a message has no `contentType` of its own, the one declared in its inline `traits` applies (the last one wins). A declared content type that does not match `application/*+avro` (the check is case-sensitive) is a violation.

An Avro message, that is, one whose `schemaFormat` (on the message in 2.x, on the `payload` in 3.x) is an `application/vnd.apache.avro` format, must also declare a content type: it is a violation when it has none and the document has no `defaultContentType`. Non-Avro messages without a content type are not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: application/json # Noncompliant {{AAR060: contentType 'application/json' must match 'application/*+avro'.}}
channels:
  orders.evt.order.created:
    subscribe:
      operationId: receiveOrderCreated
      message:
        contentType: application/avro # Noncompliant {{AAR060: contentType 'application/avro' must match 'application/*+avro'.}}
        schemaFormat: application/vnd.apache.avro;version=1.9.0
        payload:
          type: record
          name: OrderCreated
          fields:
            - name: orderId
              type: string
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
defaultContentType: application/vnd.orders.v1+avro
channels:
  orders.evt.order.created:
    subscribe:
      operationId: receiveOrderCreated
      message:
        contentType: application/vnd.orders.v1+avro
        schemaFormat: application/vnd.apache.avro;version=1.9.0
        payload:
          type: record
          name: OrderCreated
          fields:
            - name: orderId
              type: string
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.evt.order.created
    messages:
      OrderCreated: # Noncompliant {{AAR060: An Avro message must declare a contentType matching 'application/*+avro'.}}
        payload:
          schemaFormat: application/vnd.apache.avro;version=1.9.0
          schema:
            type: record
            name: OrderCreated
            fields:
              - name: orderId
                type: string
components:
  messages:
    OrderCancelled:
      contentType: application/vnd.orders.v1+json # Noncompliant {{AAR060: contentType 'application/vnd.orders.v1+json' must match 'application/*+avro'.}}
      payload:
        type: object
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.evt.order.created
    messages:
      OrderCreated:
        contentType: application/vnd.orders.v1+avro
        payload:
          schemaFormat: application/vnd.apache.avro;version=1.9.0
          schema:
            type: record
            name: OrderCreated
            fields:
              - name: orderId
                type: string
components:
  messages:
    OrderCancelled:
      contentType: application/vnd.orders.v1+avro
      payload:
        type: object
```
