Retry topics must follow the naming pattern Spring relies on to reprocess failed messages automatically: `<topicOriginal>.<consumerGroup>.retry.<n>` (e.g. `beca.cmd.alumnos.solicitud.beca.grupo1.retry.1`).

The rule checks every channel whose name contains `.retry.`: the channel key in AsyncAPI 2.x, and the channel `address` in AsyncAPI 3.x (a channel with a null `address` is skipped, and one without an `address` field is checked by its key). Channels whose name does not contain `.retry.` are ignored.

A retry channel name complies when it has at least two dot-separated segments before `.retry.` (the original topic followed by the consumer group), every segment is made of lowercase letters and digits, optionally joined by hyphens, and the name ends with `.retry.` followed by a number. Uppercase letters, underscores, a missing or non-numeric retry number, a trailing segment after the number or a single segment before `.retry.` are violations.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Payments Events
  version: 1.0.0
channels:
  payments.evt.payment.created:
    subscribe:
      operationId: receivePaymentCreated
      message:
        payload:
          type: object
  billing.retry.1: # Noncompliant {{AAR058: Channel name 'billing.retry.1' contains '.retry.' but does not follow the required pattern '<topicOriginal>.<consumerGroup>.retry.<n>' (e.g. 'beca.cmd.alumnos.solicitud.beca.grupo1.retry.1') required by Spring for automatic retry reprocessing.}}
    subscribe:
      operationId: receivePaymentCreatedRetryShort
      message:
        payload:
          type: object
  payments.evt.payment.created.billing_group.retry.first: # Noncompliant {{AAR058: Channel name 'payments.evt.payment.created.billing_group.retry.first' contains '.retry.' but does not follow the required pattern '<topicOriginal>.<consumerGroup>.retry.<n>' (e.g. 'beca.cmd.alumnos.solicitud.beca.grupo1.retry.1') required by Spring for automatic retry reprocessing.}}
    subscribe:
      operationId: receivePaymentCreatedRetryFirst
      message:
        payload:
          type: object
```
