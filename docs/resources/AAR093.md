Every operation must declare its Kafka binding, so that the producer or consumer settings of each operation are documented.

In AsyncAPI 3.x the rule checks every operation of the root `operations` object and of `components.operations`; in AsyncAPI 2.x, every `publish` and `subscribe` operation of the channels in `channels` and `components.channels`. The operation must declare `bindings` with a `kafka` entry whose value is an object; any object is accepted, an empty `{}` included. Kafka bindings of channels, messages or servers do not count.

A `kafka` binding inherited from an operation trait counts: in 2.x a trait's binding overrides the operation's own one, while in 3.x the operation's own binding wins. An operation without a `kafka` binding is reported on its `bindings` field, or on the operation when it has no `bindings`, and a `kafka` entry that is not an object (for example an empty value) is reported on that entry.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish: # Noncompliant {{AAR093: The publish operation of channel 'orders.created' must declare a 'kafka' binding.}}
      operationId: publishOrderCreated
      message:
        payload:
          type: object
    subscribe:
      operationId: consumeOrderCreated
      bindings: # Noncompliant {{AAR093: The subscribe operation of channel 'orders.created' must declare a 'kafka' binding.}}
        amqp:
          ack: true
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      bindings:
        kafka:
          clientId:
            type: string
            enum:
              - orders-service
          bindingVersion: 0.4.0
      message:
        payload:
          type: object
    subscribe:
      operationId: consumeOrderCreated
      traits:
        - $ref: '#/components/operationTraits/orderConsumer'
      message:
        payload:
          type: object
components:
  operationTraits:
    orderConsumer:
      bindings:
        kafka:
          groupId:
            type: string
            enum:
              - billing-service
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    bindings:
      kafka:
        topic: orders.created
operations:
  sendOrderCreated: # Noncompliant {{AAR093: Operation 'sendOrderCreated' must declare a 'kafka' binding.}}
    action: send
    channel:
      $ref: '#/channels/orderCreated'
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    bindings:
      kafka: # Noncompliant {{AAR093: The 'kafka' binding of operation 'receiveOrderCreated' must be an object.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
operations:
  sendOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
    bindings:
      kafka: {}
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    traits:
      - $ref: '#/components/operationTraits/orderConsumer'
components:
  operationTraits:
    orderConsumer:
      bindings:
        kafka:
          groupId:
            type: string
            enum:
              - billing-service
          bindingVersion: 0.5.0
```
