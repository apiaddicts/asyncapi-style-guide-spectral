Every named Avro schema must declare a namespace that follows the corporate pattern, so that the fully qualified type names registered in the schema registry are unique and traceable to their application.

A named Avro schema is any object whose `type` is `record`, `enum` or `fixed`, wherever it appears in the document: message payloads (in AsyncAPI 3.x, the `schema` of a multi-format payload), headers, parameters or components. Its `namespace` is required and, by default, must be `org.madrid.<cod_poaps>.<classification>.<domain>` for application schemas or `org.madrid.common.<domain>` for common schemas, each segment made of lowercase letters, digits, `_` or `-`. A missing namespace and a namespace that does not match are reported on the schema. Named types declared inside the `fields` of a record are not checked separately.

Parameters
----------

- `pattern` — regular expression the namespace must match, written plainly (for example `^org\.madrid\.[a-z0-9_-]+$`). An empty value falls back to the default. Default: `^org\.madrid\.(common\.[a-z0-9_-]+|[a-z0-9_-]+\.[a-z0-9_-]+\.[a-z0-9_-]+)$`.
