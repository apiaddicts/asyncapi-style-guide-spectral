Avro payloads must declare a standard Avro schema format with a version allowed by the organization, so that every tool reading the document resolves a known Avro version.

Every `schemaFormat` value that refers to Avro (it contains `application/vnd.apache.avro`, in any letter case) must be exactly `application/vnd.apache.avro;version=<version>`, `application/vnd.apache.avro+json;version=<version>` or `application/vnd.apache.avro+yaml;version=<version>`, where `<version>` is one of the configured allowed versions. By default the only allowed version is `1.9.0`. Any other version, a missing version, a different letter case, spacing or an extra parameter is reported. Non-Avro formats are not checked. In AsyncAPI 2.x `schemaFormat` is declared on the message; in AsyncAPI 3.x it is declared on the multi-format schema object, such as a message `payload`.

Parameters
----------

- `allowedVersions` (default `1.9.0`): comma-separated list of the allowed Avro versions. Entries are trimmed, empty entries are dropped, and the `version` parameter of the `schemaFormat` must match an entry exactly.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Scholarship Requests
  version: 1.0.0
channels:
  beca.cmd.alumnos.solicitud.beca:
    publish:
      operationId: publishScholarshipRequested
      message:
        name: ScholarshipRequested
        schemaFormat: application/vnd.apache.avro;version=1.11.1 # Noncompliant {{AAR056: The 'schemaFormat' value 'application/vnd.apache.avro;version=1.11.1' must be 'application/vnd.apache.avro[+json|+yaml];version=<version>' with a version allowed by the organization (1.9.0) when the payload uses Avro.}}
        payload:
          type: record
          name: ScholarshipRequested
          namespace: org.madrid.beca.cmd.alumnos
          fields:
            - name: studentId
              type: string
```
