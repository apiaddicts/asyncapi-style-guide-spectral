The `description` of an operation should explain it in more detail than its `summary`, instead of repeating it.

In AsyncAPI 2 the rule checks the `publish` and `subscribe` operations of every channel in `channels`. An operation that has no `description` field is reported. AsyncAPI 3 operations are not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish: # Noncompliant {{AAR022: The 'description' field must not be identical to the 'summary' field.}}
      operationId: publishOrderCreated
      summary: Publish an event when an order is created.
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      summary: Publish an event when an order is created.
      description: Publishes the order with its lines and totals once the payment has been authorized.
      message:
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

This rule does not apply to AsyncAPI 3.x documents.

Compliant Solution (AsyncAPI 3)
-------------------------------

This rule does not apply to AsyncAPI 3.x documents.
