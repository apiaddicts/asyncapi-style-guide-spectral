Every operation must say which messages it sends or receives, so that producers and consumers agree on what travels through it.

In AsyncAPI 2.x the rule checks every `publish` and `subscribe` operation of the channels in `channels` and `components.channels`: it must declare a usable `message`, that is, an object, a local reference that resolves to an object, or an external reference; when the message is a `oneOf`, at least one of its items must be usable. A missing `message` is reported on the operation and an unusable one on `message`.

In AsyncAPI 3.x the rule checks every operation of the root `operations` object and of `components.operations`. An operation that declares `messages` must list at least one usable message in it, so an empty list (`messages: []`), a value that is not a list, or a list whose entries are all unusable is reported on `messages`. An operation that omits `messages` is not reported, because it takes every message of its channel, and the messages of its replies never count.

In both versions operation traits never supply messages, and an operation that is not an object is reported too.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    description: Orders that have just been created.
    publish: # Noncompliant {{AAR094: The publish operation of channel 'orders.created' must declare a 'message'.}}
      operationId: publishOrderCreated
      summary: Publish an order once it has been created.
    subscribe:
      operationId: consumeOrderCreated
      summary: Consume the created orders.
      message: # Noncompliant {{AAR094: The 'message' of the subscribe operation of channel 'orders.created' must declare at least one message.}}
        oneOf: []
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    description: Orders that have just been created.
    publish:
      operationId: publishOrderCreated
      summary: Publish an order once it has been created.
      message:
        payload:
          type: object
    subscribe:
      operationId: consumeOrderCreated
      summary: Consume the created orders.
      message:
        oneOf:
          - $ref: '#/components/messages/orderCreated'
          - $ref: '#/components/messages/orderCreatedLegacy'
components:
  messages:
    orderCreated:
      payload:
        type: object
    orderCreatedLegacy:
      payload:
        type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object
operations:
  sendOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
    messages: [] # Noncompliant {{AAR094: The 'messages' of operation 'sendOrderCreated' must declare at least one message.}}
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    messages: # Noncompliant {{AAR094: The 'messages' of operation 'receiveOrderCreated' must declare at least one message.}}
      - $ref: '#/channels/orderCreated/messages/orderUpdated'
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object
operations:
  sendOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
    messages:
      - $ref: '#/channels/orderCreated/messages/orderCreated'
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
```
