Every message must provide at least one example, so that consumers can see what the events on the broker look like.

The rule checks the messages of `channels`, `components.channels` and `components.messages`. In AsyncAPI 2.x these are the messages of the `publish` and `subscribe` operations, including each `oneOf` alternative; in AsyncAPI 3.x they are the entries of the channel `messages` maps. The `examples` provided by the message traits a message applies also count; when both the message and its traits declare `examples`, the list that prevails is the one the trait merge of each version keeps (in 2.x the traits override the message, in 3.x the message overrides its traits).

A message with a `payload` must have an example that declares `payload`; a message without `payload` must have an example that declares `payload` or non-empty `headers`. A message without `examples`, with an empty or non-array `examples` value, or whose examples provide none of that content, is a violation.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message: # Noncompliant {{AAR071: Message must provide at least one example with a sample 'payload'.}}
        messageId: orderPlaced
        payload:
          type: object
          properties:
            orderId:
              type: string
  orders.cancelled:
    publish:
      message:
        messageId: orderCancelled
        payload:
          type: object
          properties:
            orderId:
              type: string
        examples: # Noncompliant {{AAR071: Message 'examples' must contain at least one example with a sample 'payload'.}}
          - name: cancelledByCustomer
            headers:
              correlationId: 3f2c9a1e
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        payload:
          type: object
          properties:
            orderId:
              type: string
        examples:
          - name: standardOrder
            payload:
              orderId: ORD-1001
  orders.cancelled:
    publish:
      message:
        messageId: orderCancelled
        payload:
          type: object
          properties:
            orderId:
              type: string
        examples:
          - name: cancelledByCustomer
            headers:
              correlationId: 3f2c9a1e
            payload:
              orderId: ORD-1002
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced: # Noncompliant {{AAR071: Message must provide at least one example with a sample 'payload'.}}
        payload:
          type: object
          properties:
            orderId:
              type: string
components:
  messages:
    orderHeartbeat:
      headers:
        type: object
        properties:
          producerId:
            type: string
      examples: [] # Noncompliant {{AAR071: Message 'examples' must contain at least one example with a 'payload' or non-empty 'headers'.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        payload:
          type: object
          properties:
            orderId:
              type: string
        examples:
          - name: standardOrder
            payload:
              orderId: ORD-1001
components:
  messages:
    orderHeartbeat:
      headers:
        type: object
        properties:
          producerId:
            type: string
      examples:
        - headers:
            producerId: orders-service
```
