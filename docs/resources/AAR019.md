The document must declare an `id`, a URI that identifies the application it describes.

The root of the document must contain a non-empty `id` field. A document without it is reported, in both AsyncAPI 2.x and 3.x.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0 # Noncompliant {{AAR019: The AsyncAPI document should define an 'id' field.}}
info:
  title: Orders Events
  version: 1.0.0
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
id: urn:es:quality:orders-events
info:
  title: Orders Events
  version: 1.0.0
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0 # Noncompliant {{AAR019: The AsyncAPI document should define an 'id' field.}}
info:
  title: Orders Events
  version: 1.0.0
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
id: urn:es:quality:orders-events
info:
  title: Orders Events
  version: 1.0.0
```
