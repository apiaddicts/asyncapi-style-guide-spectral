Message identifiers and message names must follow the naming convention configured by the organization, camelCase by default, so that consumers and generated code can refer to every message in a consistent way.

In AsyncAPI 2.x the rule checks the `messageId` and the `name` of every message in `channels` (the `publish` and `subscribe` messages, including each `oneOf` alternative), `components.channels` and `components.messages`, as well as the `messageId` and `name` of the message traits declared inline in those messages and in `components.messageTraits`. In AsyncAPI 3.x, where a message is identified by its key, the rule checks the keys of the `messages` maps of `channels`, `components.channels` and `components.messages`, plus the `name` of every message and message trait.

A value that does not follow the convention, or that is not a string, is a violation.

Parameters
----------

- `naming-convention` — naming convention that message identifiers and names must follow. Accepted values: `camelCase`, `PascalCase`, `kebab-case` and `snake_case`; letter case, spaces, hyphens, underscores and a trailing `case` are ignored, so `camel`, `pascal`, `kebab` or `snake` also work, and `lowerCamelCase` and `UpperCamelCase` are accepted as camelCase and PascalCase. camelCase and PascalCase do not allow consecutive uppercase letters (`orderID` is rejected). An unrecognized value falls back to camelCase. Default: `camelCase`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message:
        messageId: OrderPlaced # Noncompliant {{AAR065: messageId 'OrderPlaced' must be camelCase.}}
        name: order_placed # Noncompliant {{AAR065: Message name 'order_placed' must be camelCase.}}
        traits:
          - $ref: '#/components/messageTraits/commonHeaders'
        payload:
          type: object
          properties:
            orderId:
              type: string
components:
  messageTraits:
    commonHeaders:
      name: Common Headers # Noncompliant {{AAR065: Message trait name 'Common Headers' must be camelCase.}}
      headers:
        type: object
        properties:
          correlationId:
            type: string
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        name: orderPlaced
        traits:
          - $ref: '#/components/messageTraits/commonHeaders'
        payload:
          type: object
          properties:
            orderId:
              type: string
components:
  messageTraits:
    commonHeaders:
      name: commonHeaders
      headers:
        type: object
        properties:
          correlationId:
            type: string
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      OrderPlaced: # Noncompliant {{AAR065: Message key 'OrderPlaced' must be camelCase.}}
        name: order_placed # Noncompliant {{AAR065: Message name 'order_placed' must be camelCase.}}
        payload:
          type: object
          properties:
            orderId:
              type: string
operations:
  publishOrderPlaced:
    action: send
    channel:
      $ref: '#/channels/ordersPlaced'
    messages:
      - $ref: '#/channels/ordersPlaced/messages/OrderPlaced'
```
