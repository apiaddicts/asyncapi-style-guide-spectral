Every channel operation should state the security scheme it uses, so that producers and consumers know how to authenticate against the broker for that channel.

In AsyncAPI 2.x each `publish` and `subscribe` operation of a channel must declare a `security` field with the security requirements that apply to it. An operation without `security` is reported.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - saslScram: []
channels:
  orders.created:
    publish: # Noncompliant {{AAR043: Channel 'publish.security' should define a security scheme in its operations or bindings.}}
      operationId: publishOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
    subscribe: # Noncompliant {{AAR043: Channel 'subscribe.security' should define a security scheme in its operations or bindings.}}
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
components:
  securitySchemes:
    saslScram:
      type: scramSha512
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    security:
      - saslScram: []
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      security:
        - saslScram: []
      message:
        name: OrderCreated
        payload:
          type: object
    subscribe:
      operationId: onOrderCreated
      security:
        - saslScram: []
      message:
        name: OrderCreated
        payload:
          type: object
components:
  securitySchemes:
    saslScram:
      type: scramSha512
```
