Every server name must start with one of the server types approved by the organization, so that the kind of broker behind each server is clear from its name.

The rule checks each key of the root `servers` object, in AsyncAPI 2.x and 3.x alike. A name passes when it is exactly an approved type or starts with one followed by `-` or `_`, such as `kafka`, `kafka-pro` or `eventstreams_dev`. The comparison is case-sensitive, so names like `production`, `Kafka-pro`, `kafkapro` or `kafka.pro` are reported. By default the approved types are `eventstreams` and `kafka`. The servers under `components.servers` and the `servers` lists of channels are not checked.

Parameters
----------

- `allowed-server-types` — comma-separated list of the approved server types, such as `kafka,mqtt`. Entries are trimmed, empty and repeated entries are ignored, and each type is compared exactly, case included. An empty value falls back to the default. Default: `eventstreams,kafka`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production: # Noncompliant {{AAR082: Server name 'production' must start with an approved server type: 'eventstreams', 'kafka'.}}
    url: broker.quality.es:9093
    protocol: kafka-secure
  Kafka-pre: # Noncompliant {{AAR082: Server name 'Kafka-pre' must start with an approved server type: 'eventstreams', 'kafka'.}}
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  kafka-pro:
    url: broker.quality.es:9093
    protocol: kafka-secure
  kafka_pre:
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
channels: {}
```
