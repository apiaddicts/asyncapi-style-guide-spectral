Every operation must be identified by a camelCase name, so that operations are named consistently and code generators produce predictable method names.

In AsyncAPI 2.x each `publish` and `subscribe` operation of the channels, including the channels under `components.channels`, must declare an `operationId`. A missing `operationId` is reported on the operation, and a value that is not camelCase (a lowercase letter followed only by letters and digits, such as `solicitarBeca`) is reported on the field.

In AsyncAPI 3.x operations have no `operationId`: they are identified by their key in the `operations` map. Every key of `operations` and of `components.operations` that is not camelCase is reported. Keys starting with `x-` are ignored.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish: # Noncompliant {{AAR051: Operation must declare an 'operationId'.}}
      message:
        name: OrderCreated
        payload:
          type: object
    subscribe:
      operationId: on_order_created # Noncompliant {{AAR051: 'operationId' must follow camelCase naming convention (e.g. 'solicitarBeca'). Found: 'on_order_created'.}}
      message:
        name: OrderCreated
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
    subscribe:
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object
operations:
  send-order-created: # Noncompliant {{AAR051: The operation key must follow camelCase naming convention (e.g. 'solicitarBeca'). Found: 'send-order-created'.}}
    action: send
    channel:
      $ref: '#/channels/orderCreated'
  ReceiveOrderCreated: # Noncompliant {{AAR051: The operation key must follow camelCase naming convention (e.g. 'solicitarBeca'). Found: 'ReceiveOrderCreated'.}}
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        payload:
          type: object
operations:
  sendOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
```
