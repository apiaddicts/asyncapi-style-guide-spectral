The API must say who is responsible for it, so the `info` object must declare a `contact` object with a non-empty `name` and `email`.

The rule checks `info.contact` in AsyncAPI 2.x and 3.x alike. A document without `info`, an `info` without `contact`, a `contact` that is not an object, a missing `name` or `email`, or one of them empty (`null`, or a string made only of whitespace) is a violation.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info: # Noncompliant {{AAR077: The 'info' object must declare a 'contact' object with 'name' and 'email'.}}
  title: Orders Events
  version: 1.0.0
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  contact:
    name: Orders Team
    email: orders-team@quality.es
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  contact: # Noncompliant {{AAR077: The 'contact' object must declare 'email'.}}
    name: '' # Noncompliant {{AAR077: The 'name' of the 'contact' object must not be empty.}}
    url: https://quality.es/orders-team
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  contact:
    name: Orders Team
    email: orders-team@quality.es
    url: https://quality.es/orders-team
```
