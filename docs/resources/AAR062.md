Every consuming operation must declare its consumer group, so that the messaging platform can bind it to a durable, load-balanced consumer group.

The rule checks the `subscribe` operations of the channels under `channels` and `components.channels` in AsyncAPI 2.x, and the operations with `action: receive` under `operations` and `components.operations` in AsyncAPI 3.x. Producing operations are not checked, and an operation referenced with `$ref` is checked where it is defined.

The consumer group is declared with a non-empty `x-scs-group` value, or with a `bindings.kafka.groupId` (usually a schema object listing the group). An operation with neither is a violation, including one whose `x-scs-group` is empty, whitespace-only, an object or an array, and one whose Kafka bindings have no `groupId`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.evt.order.created:
    subscribe: # Noncompliant {{AAR062: The consuming operation must declare a consumer group via 'x-scs-group' or 'bindings.kafka.groupId'.}}
      operationId: receiveOrderCreated
      message:
        payload:
          type: object
  orders.evt.order.cancelled:
    subscribe: # Noncompliant {{AAR062: The consuming operation must declare a consumer group via 'x-scs-group' or 'bindings.kafka.groupId'.}}
      operationId: receiveOrderCancelled
      bindings:
        kafka:
          clientId:
            type: string
            enum:
              - orders-service
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.evt.order.created:
    subscribe:
      operationId: receiveOrderCreated
      x-scs-group: orders-service
      message:
        payload:
          type: object
  orders.evt.order.cancelled:
    subscribe:
      operationId: receiveOrderCancelled
      bindings:
        kafka:
          groupId:
            type: string
            enum:
              - orders-service
      message:
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.evt.order.created
  orderShipped:
    address: orders.evt.order.shipped
operations:
  receiveOrderCreated: # Noncompliant {{AAR062: The consuming operation must declare a consumer group via 'x-scs-group' or 'bindings.kafka.groupId'.}}
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    x-scs-group: ''
  sendOrderShipped:
    action: send
    channel:
      $ref: '#/channels/orderShipped'
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.evt.order.created
  orderShipped:
    address: orders.evt.order.shipped
operations:
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    bindings:
      kafka:
        groupId:
          type: string
          enum:
            - shipping-service
  sendOrderShipped:
    action: send
    channel:
      $ref: '#/channels/orderShipped'
```
