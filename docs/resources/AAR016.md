The contact information of the API must be complete, so that consumers can reach the team behind it.

When the `info` object has a `contact` object, it must include `name`, `url` and `email`, each with a non-empty value. A `contact` object that lacks any of these fields is reported, and so is each of them that is present but empty. The rule behaves the same in AsyncAPI 2.x and 3.x.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  contact: # Noncompliant {{Contact object must be complete (name, url, email).}}
    name: Orders Team
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  contact:
    name: Orders Team
    url: https://quality.es/teams/orders
    email: orders-team@quality.es
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  contact:
    name: Orders Team
    url: https://quality.es/teams/orders
    email: "" # Noncompliant {{Contact object must be complete (name, url, email).}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  contact:
    name: Orders Team
    url: https://quality.es/teams/orders
    email: orders-team@quality.es
```
