Every link to external documentation must say what it points to, so each External Documentation object must declare a non-empty `description` and `url`.

The rule checks every `externalDocs` in the document. In AsyncAPI 2.x these are the root `externalDocs` and those of tags, `publish` and `subscribe` operations, messages (including each `oneOf` alternative), operation traits, message traits and schemas (message payloads and headers, channel parameters and `components.schemas`). In AsyncAPI 3.x they are those of `info`, servers, channels, operations, messages, operation traits, message traits, tags and schemas, both inline and in `components`, plus the entries of `components.externalDocs`. Schemas are inspected, together with their nested subschemas, when they are AsyncAPI, JSON Schema or OpenAPI schemas; schemas in other formats, such as Avro, are not.

A missing `description` or `url`, a field that is empty (`null`, or a string made only of whitespace), or an `externalDocs` value that is not an object is a violation.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
externalDocs: # Noncompliant {{AAR079: The 'externalDocs' object must declare 'description'.}}
  url: https://docs.quality.es/orders
channels:
  orders.placed:
    publish:
      externalDocs:
        description: Order placement flow.
        url: '' # Noncompliant {{AAR079: The 'url' of the 'externalDocs' object must not be empty.}}
      message:
        messageId: orderPlaced
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
externalDocs:
  description: Orders platform guide.
  url: https://docs.quality.es/orders
channels:
  orders.placed:
    publish:
      externalDocs:
        description: Order placement flow.
        url: https://docs.quality.es/orders/placement
      message:
        messageId: orderPlaced
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  externalDocs:
    $ref: '#/components/externalDocs/ordersGuide'
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        payload:
          type: object
          properties:
            orderId:
              type: string
              externalDocs: # Noncompliant {{AAR079: The 'externalDocs' object must declare 'description'.}}
                url: https://docs.quality.es/orders/identifiers
components:
  externalDocs:
    ordersGuide: # Noncompliant {{AAR079: The 'externalDocs' object must declare 'url'.}}
      description: Orders platform guide.
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  externalDocs:
    $ref: '#/components/externalDocs/ordersGuide'
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        payload:
          type: object
          properties:
            orderId:
              type: string
              externalDocs:
                description: Order identifier format.
                url: https://docs.quality.es/orders/identifiers
components:
  externalDocs:
    ordersGuide:
      description: Orders platform guide.
      url: https://docs.quality.es/orders
```
