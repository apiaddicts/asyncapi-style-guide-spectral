Each `operationId` must be unique in the document, so that every operation can be identified unambiguously.

The rule compares the `operationId` of the `publish` and `subscribe` operations of every channel in `channels`. Every operation that repeats an `operationId` already used by an earlier operation is reported, together with the location where that `operationId` was first defined.

The rule applies only to AsyncAPI 2.x documents; in AsyncAPI 3 each operation is identified by its key in the `operations` object.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderEvent
      message:
        payload:
          type: object
  orders.cancelled:
    publish:
      operationId: publishOrderEvent # Noncompliant {{AAR013: Duplicate operationId 'publishOrderEvent' found. First defined at 'channels.orders.created.publish.operationId'.}}
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      message:
        payload:
          type: object
  orders.cancelled:
    publish:
      operationId: publishOrderCancelled
      message:
        payload:
          type: object
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

This rule does not apply to AsyncAPI 3.x documents.

Compliant Solution (AsyncAPI 3)
-------------------------------

This rule does not apply to AsyncAPI 3.x documents.
