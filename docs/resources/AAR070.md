The `bindingVersion` of every protocol binding must match the pattern configured by the organization, by default a semantic version with three numeric parts such as `0.4.0`, so that tools know exactly which version of the binding specification applies.

The rule checks the bindings of servers, channels, operations, messages, operation traits and message traits, both inline and in `components`, as well as the reusable bindings of `components.serverBindings`, `components.channelBindings`, `components.operationBindings` and `components.messageBindings`. In AsyncAPI 2.x the operations are the `publish` and `subscribe` objects of each channel and the messages include each `oneOf` alternative; in AsyncAPI 3.x the operations are the entries of `operations` and the messages those of the channel `messages` maps.

A `bindingVersion` that does not match the pattern, or that is not a string, is a violation. Bindings without `bindingVersion` and specification extensions (`x-` keys) are not checked.

Parameters
----------

- `pattern` — regular expression that every `bindingVersion` must match, written plainly (for example `^0\.\d+\.\d+$`) or as a `/source/flags` literal (for example `/^v?\d+\.\d+\.\d+$/i`). It is applied unanchored, so include `^` and `$` to constrain the whole value. A blank or invalid expression falls back to the default. Default: `^\d+\.\d+\.\d+$`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
    bindings:
      kafka:
        schemaRegistryUrl: https://registry.quality.es
        bindingVersion: latest # Noncompliant {{AAR070: Server binding 'kafka' bindingVersion 'latest' must match '^\d+\.\d+\.\d+$'.}}
channels:
  orders.placed:
    bindings:
      kafka:
        partitions: 6
        bindingVersion: '0.4' # Noncompliant {{AAR070: Channel binding 'kafka' bindingVersion '0.4' must match '^\d+\.\d+\.\d+$'.}}
    publish:
      bindings:
        kafka:
          clientId:
            type: string
          bindingVersion: 0.4.0
      message:
        messageId: orderPlaced
        payload:
          type: object
```
