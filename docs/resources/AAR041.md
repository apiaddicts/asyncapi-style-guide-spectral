Servers and channels should be defined as reusable components, so that they can be referenced from several places instead of being repeated.

When the document declares a `components` object, it must contain both a `servers` map and a `channels` map; the `components` object is reported when either of them is missing. The rule works the same way in AsyncAPI 2.x and 3.x, and a document without `components` is not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
channels:
  orders.created:
    subscribe:
      operationId: onOrderCreated
      message:
        $ref: '#/components/messages/OrderCreated'
components: # Noncompliant {{AAR041: Consider defining reusable server and channel references in 'components'.}}
  messages:
    OrderCreated:
      name: OrderCreated
      payload:
        type: object
        properties:
          orderId:
            type: string
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/production'
channels:
  orders.created:
    $ref: '#/components/channels/ordersCreated'
components:
  servers:
    production:
      url: broker.quality.es:9093
      protocol: kafka-secure
  channels:
    ordersCreated:
      subscribe:
        operationId: onOrderCreated
        message:
          $ref: '#/components/messages/OrderCreated'
  messages:
    OrderCreated:
      name: OrderCreated
      payload:
        type: object
        properties:
          orderId:
            type: string
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    host: broker.quality.es:9093
    protocol: kafka-secure
channels:
  orderCreated:
    address: orders.created
    messages:
      orderCreated:
        $ref: '#/components/messages/OrderCreated'
components: # Noncompliant {{AAR041: Consider defining reusable server and channel references in 'components'.}}
  servers:
    backup:
      host: broker-backup.quality.es:9093
      protocol: kafka-secure
  messages:
    OrderCreated:
      payload:
        type: object
        properties:
          orderId:
            type: string
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/production'
channels:
  orderCreated:
    $ref: '#/components/channels/orderCreated'
components:
  servers:
    production:
      host: broker.quality.es:9093
      protocol: kafka-secure
  channels:
    orderCreated:
      address: orders.created
      messages:
        orderCreated:
          $ref: '#/components/messages/OrderCreated'
  messages:
    OrderCreated:
      payload:
        type: object
        properties:
          orderId:
            type: string
```
