Every server a channel is bound to must be defined in the root `servers` object, so that the channel only points to brokers the document actually describes.

In AsyncAPI 2.x a channel restricts the servers it is available on by listing their names in its `servers` field. Each listed name that is not a key of the root `servers` object is reported, and the message names the servers that are defined. A channel without `servers` is available on every server and is not checked.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
  development:
    url: broker-dev.quality.es:9093
    protocol: kafka-secure
channels:
  orders.created:
    servers:
      - production
      - staging # Noncompliant {{AAR040: Channel 'orders.created' references server 'staging' which is not defined in the root 'servers' object. Available servers: production, development.}}
    subscribe:
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
          properties:
            orderId:
              type: string
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
  development:
    url: broker-dev.quality.es:9093
    protocol: kafka-secure
channels:
  orders.created:
    servers:
      - production
      - development
    subscribe:
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
          properties:
            orderId:
              type: string
```
