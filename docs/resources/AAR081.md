Every server name must follow the organization's naming pattern, so that servers are identified consistently across APIs.

The rule checks each key of the root `servers` object, in AsyncAPI 2.x and 3.x alike, and reports every name that does not match the configured regular expression. By default a name may only contain letters, digits, hyphens and underscores. Server hosts and the servers under `components.servers` are not checked.

Parameters
----------

- `pattern` — regular expression every server name must match. It is written plainly (`^[a-z0-9]+(-[a-z0-9]+)*$`) or as a `/source/flags` literal (`/^[a-z0-9-]+$/i`). An empty or invalid value falls back to the default. Default: `^[A-Za-z0-9_-]+$`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  kafka.production: # Noncompliant {{AAR081: Server name 'kafka.production' must match '^[A-Za-z0-9_-]+$'.}}
    url: broker.quality.es:9093
    protocol: kafka-secure
  kafka staging: # Noncompliant {{AAR081: Server name 'kafka staging' must match '^[A-Za-z0-9_-]+$'.}}
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  kafka-production:
    url: broker.quality.es:9093
    protocol: kafka-secure
  kafka_staging:
    url: broker-pre.quality.es:9093
    protocol: kafka-secure
channels: {}
```
