The examples of a message must be valid against the message schemas, so that the documented samples are events that consumers could actually receive.

The rule checks every entry of the `examples` of the messages in `channels`, `components.channels` and `components.messages` (in AsyncAPI 2.x the messages of the `publish` and `subscribe` operations, including each `oneOf` alternative; in AsyncAPI 3.x the entries of the channel `messages` maps). The `payload` of each example is validated against the message `payload` schema and its `headers` against the message `headers` schema, after applying the message traits as each version merges them, so examples and schemas inherited from traits are checked too.

Schemas are read according to their schema format: AsyncAPI Schema or JSON Schema (the default), OpenAPI 3.0 Schema Object and Avro. In AsyncAPI 2.x the format is the message `schemaFormat`; in AsyncAPI 3.x it is the `schemaFormat` of a Multi Format Schema object used as `payload` or `headers`. Schemas in other formats and external references are not validated. Every value that breaks its schema (wrong type, missing required property or record field, value outside `enum`, `pattern` or `format` mismatch, length, range or item constraints, and so on) is a violation, reported at that value.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        payload:
          type: object
          required:
            - orderId
            - amount
          properties:
            orderId:
              type: string
            amount:
              type: number
            currency:
              type: string
              enum:
                - EUR
                - USD
        examples:
          - name: standardOrder
            payload: # Noncompliant {{AAR072: examples[0].payload must have required property 'orderId'.}}
              amount: '120.50' # Noncompliant {{AAR072: examples[0].payload.amount must be a number.}}
              currency: GBP # Noncompliant {{AAR072: examples[0].payload.currency must be one of: "EUR", "USD".}}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.placed:
    publish:
      message:
        messageId: orderPlaced
        payload:
          type: object
          required:
            - orderId
            - amount
          properties:
            orderId:
              type: string
            amount:
              type: number
            currency:
              type: string
              enum:
                - EUR
                - USD
        examples:
          - name: standardOrder
            payload:
              orderId: ORD-1001
              amount: 120.5
              currency: EUR
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        headers:
          type: object
          properties:
            correlationId:
              type: string
              format: uuid
        payload:
          schemaFormat: application/vnd.apache.avro;version=1.9.0
          schema:
            type: record
            name: OrderPlaced
            fields:
              - name: orderId
                type: string
              - name: quantity
                type: int
        examples:
          - name: standardOrder
            headers:
              correlationId: not-a-uuid # Noncompliant {{AAR072: examples[0].headers.correlationId must match format "uuid".}}
            payload:
              orderId: ORD-1001
              quantity: two # Noncompliant {{AAR072: examples[0].payload.quantity must be an int.}}
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  ordersPlaced:
    address: orders.placed
    messages:
      orderPlaced:
        headers:
          type: object
          properties:
            correlationId:
              type: string
              format: uuid
        payload:
          schemaFormat: application/vnd.apache.avro;version=1.9.0
          schema:
            type: record
            name: OrderPlaced
            fields:
              - name: orderId
                type: string
              - name: quantity
                type: int
        examples:
          - name: standardOrder
            headers:
              correlationId: 7d4b2f8e-1c3a-4e5f-9a6b-2c8d0e1f3a5b
            payload:
              orderId: ORD-1001
              quantity: 2
```
