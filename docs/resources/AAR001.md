Every server must use a secure protocol, so that messages travel encrypted between clients and brokers.

The `protocol` of each server in the root `servers` object must match the configured regular expression. A server given by `$ref` is checked where it is defined, once. The expression is tested against the protocol as written, case included unless the expression says otherwise. A server without `protocol`, or with a `protocol` that is not a string, is not reported by this rule. By default only `https`, `wss`, `amqps`, `kafka-secure` and `secure-mqtt` are accepted.

Parameters
----------

- `pattern` — regular expression every server protocol must match. It is written plainly (`^(kafka|kafka-secure)$`) or as a `/source/flags` literal (`/^(kafka|https)$/i`). Anchor it with `^` and `$` to accept whole protocol names only: `kafka` alone also accepts `kafka-secure` or `kafka-ssl`. An empty or invalid value falls back to the default. Default: `^(https|wss|amqps|kafka-secure|secure-mqtt)$`.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9092
    protocol: kafka # Noncompliant {{AAR001: Server protocol 'kafka' must match '^(https|wss|amqps|kafka-secure|secure-mqtt)$'.}}
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
servers:
  production:
    url: broker.quality.es:9093
    protocol: kafka-secure
channels: {}
```
