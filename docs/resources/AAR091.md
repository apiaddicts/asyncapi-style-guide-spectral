Every channel that declares its messages must include at least one of them, so that consumers know what they will receive on it.

The rule only applies to AsyncAPI 3.x documents. It checks every channel of the root `channels` object and of `components.channels` that declares `messages`: the map must include at least one usable message, that is, an object, a local reference that resolves to an object, or an external reference. An empty map, a value that is not a map, or a map whose entries are all unusable (for example `null`, strings, lists or references that resolve to nothing) is reported once on the `messages` of the channel.

Channels without `messages` and channels that are not objects are not reported, and the messages listed by operations or replies never count for their channel.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

This rule does not apply to AsyncAPI 2.x documents.

Compliant Solution (AsyncAPI 2)
-------------------------------

This rule does not apply to AsyncAPI 2.x documents.

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    description: Orders that have just been created.
    messages: {} # Noncompliant {{AAR091: The 'messages' of channel 'orderCreated' must declare at least one message.}}
components:
  channels:
    orderCancelled:
      address: orders.cancelled
      description: Orders cancelled by the customer.
      messages: # Noncompliant {{AAR091: The 'messages' of channel 'orderCancelled' must declare at least one message.}}
        orderCancelled:
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
    description: Orders that have just been created.
    messages:
      orderCreated:
        payload:
          type: object
components:
  channels:
    orderCancelled:
      address: orders.cancelled
      description: Orders cancelled by the customer.
      messages:
        orderCancelled:
          $ref: '#/components/messages/orderCancelled'
  messages:
    orderCancelled:
      payload:
        type: object
```
