Every operation must say what it does and, in AsyncAPI 3.x, which action it performs on which channel, so that each operation can be understood on its own.

In AsyncAPI 3.x the rule checks every operation of the root `operations` object and of `components.operations`: it must declare a non-empty `action`, `channel` and `summary`. In AsyncAPI 2.x, where the action is the `publish` or `subscribe` key and the channel is the enclosing one, the rule checks that every `publish` and `subscribe` operation of the channels in `channels` and `components.channels` declares a non-empty `summary`.

A summary inherited from an operation trait counts: in 2.x a trait's `summary` overrides the operation's own one, while in 3.x the operation's own `summary` wins; `action` and `channel` must always be declared by the operation itself. A missing field is reported on the operation, and an empty one (a blank string, `null`, an empty object or an empty list) on the field itself.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish: # Noncompliant {{AAR092: The publish operation of channel 'orders.created' must declare 'summary'.}}
      operationId: publishOrderCreated
      message:
        payload:
          type: object
    subscribe:
      operationId: consumeOrderCreated
      summary: '' # Noncompliant {{AAR092: The 'summary' of the subscribe operation of channel 'orders.created' must not be empty.}}
      message:
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orders.created:
    publish:
      operationId: publishOrderCreated
      summary: Publish an order once it has been created.
      message:
        payload:
          type: object
    subscribe:
      operationId: consumeOrderCreated
      traits:
        - $ref: '#/components/operationTraits/orderConsumer'
      message:
        payload:
          type: object
components:
  operationTraits:
    orderConsumer:
      summary: Consume the created orders.
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
operations:
  sendOrderCreated: # Noncompliant {{AAR092: Operation 'sendOrderCreated' must declare 'summary'.}}
    action: send
    channel:
      $ref: '#/channels/orderCreated'
  receiveOrderCreated:
    action: '' # Noncompliant {{AAR092: The 'action' of operation 'receiveOrderCreated' must not be empty.}}
    channel:
      $ref: '#/channels/orderCreated'
    summary: Receive the created orders.
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
channels:
  orderCreated:
    address: orders.created
operations:
  sendOrderCreated:
    action: send
    channel:
      $ref: '#/channels/orderCreated'
    summary: Send an order once it has been created.
  receiveOrderCreated:
    action: receive
    channel:
      $ref: '#/channels/orderCreated'
    traits:
      - $ref: '#/components/operationTraits/orderConsumer'
components:
  operationTraits:
    orderConsumer:
      summary: Receive the created orders.
```
