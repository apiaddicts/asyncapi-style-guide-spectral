The `info` object must identify and explain the API, so it must declare a non-empty `title`, `version` and `description`.

The rule checks the root `info` object in AsyncAPI 2.x and 3.x alike. A document without `info`, an `info` that is not an object, a missing field, or a field that is empty (`null`, or a string made only of whitespace) is a violation.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info: # Noncompliant {{AAR075: The 'info' object must declare 'description'.}}
  title: Orders Events
  version: 1.0.0
channels: {}
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  description: Events published by the order management service.
channels: {}
```

Noncompliant Code Example (AsyncAPI 3)
--------------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: '  ' # Noncompliant {{AAR075: The 'title' of the 'info' object must not be empty.}}
  version: 1.0.0
  description: Events published by the order management service.
```

Compliant Solution (AsyncAPI 3)
-------------------------------

```yaml
asyncapi: 3.0.0
info:
  title: Orders Events
  version: 1.0.0
  description: Events published by the order management service.
```
