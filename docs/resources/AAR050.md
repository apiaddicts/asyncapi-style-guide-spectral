The `info` object must contain a non-empty `title`, so that the API can be identified in catalogs, portals and generated documentation.

The rule reports the `info` object when it has no `title`, and the `title` field when its value is empty. It works the same way in AsyncAPI 2.x and 3.x.

Noncompliant Code Example (AsyncAPI 2)
--------------------------------------

```yaml
asyncapi: 2.6.0
info: # Noncompliant {{AAR050: The 'info' object must contain a non-empty 'title' field.}}
  version: 1.0.0
  description: Events published when orders change state.
channels:
  orders.created:
    subscribe:
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
```

Compliant Solution (AsyncAPI 2)
-------------------------------

```yaml
asyncapi: 2.6.0
info:
  title: Orders Events
  version: 1.0.0
  description: Events published when orders change state.
channels:
  orders.created:
    subscribe:
      operationId: onOrderCreated
      message:
        name: OrderCreated
        payload:
          type: object
```
